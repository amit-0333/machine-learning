## 1. Recap of KNN

**KNN (K-Nearest Neighbours)** predicts for a new point by looking at the **K most similar training points** ("neighbours").

- **Classification:** neighbours *vote* → most common class wins.
- **Regression:** neighbours *average* → the mean of their numbers is the answer.

Two facts to remember:
- **Lazy learner:** there is no real "training". It just memorises the data.
- **Distance-based:** so features must be on the **same scale** (standardise first), and small **K** → overfitting, large **K** → underfitting.

---

## 2. KNN Regressor

**Idea:** to predict a number, find the K closest training examples and **average their target values**.

### Worked example (1 feature)
Training data: `x` = years of experience, `y` = salary (in thousands).

| x | 1 | 2 | 3 | 6 | 7 | 9 |
|---|---|---|---|---|---|---|
| y | 10 | 12 | 15 | 30 | 34 | 45 |

**Predict for x = 4.2 with K = 3.**

1. Distance of each point to 4.2: `3.2, 2.2, 1.2, 1.8, 2.8, 4.8`
2. The 3 smallest: **x=3** (1.2), **x=6** (1.8), **x=2** (2.2)
3. Their targets: `15, 30, 12`
4. Average: `(15 + 30 + 12) / 3 =` **19**

```
y
45|                         •
34|                     •
30|              •
15|        •   ?          <- query at 4.2
12|     •
10|  •
  +--------------------------- x
    1  2  3 4.2  6  7    9
```

### How this differs from classification
| | Classifier | Regressor |
|---|---|---|
| Output | A class label | A continuous number |
| Combine neighbours by | Majority vote | Mean (or weighted mean) |
| Score with | Accuracy, F1 | RMSE, MAE, R² |

### What the prediction curve looks like
A KNN regressor draws a **step-like curve** (it only outputs averages of real training targets):
- **K = 1:** passes through every training point, so it is very wiggly and **overfits**.
- **Very large K:** nearly a flat line near the overall mean, so it **underfits**.
- **Moderate K:** follows the trend and ignores noise.

> ⚠️ KNN can't extrapolate. Beyond the training range it just repeats the average of the edge points.

## 3. Hyperparameters

A **hyperparameter** is a setting *you* choose before training. The model does not learn it. KNN has very few parameters to learn (none!), so hyperparameters are everything.

| Hyperparameter | What it controls | Typical choices | Advice |
|---|---|---|---|
| `n_neighbors` (K) | How many neighbours vote | 1 to ~30 | **Most important.** Tune with cross-validation. |
| `weights` | Does each neighbour count equally? | `uniform`, `distance` | Try `distance` when neighbours vary a lot in how far they are. |
| `metric` / `p` | How "distance" is measured | Euclidean (`p=2`), Manhattan (`p=1`) | Depends on your data (see §5). |
| `algorithm` | How neighbours are searched | `brute`, `kd_tree`, `ball_tree`, `auto` | Affects **speed only**, not the answer (see §6–7). |
| `leaf_size` | Points per leaf in tree algorithms | default 30 | Affects speed and memory only. |
| `n_jobs` | CPU cores used | `-1` = all | Speeds up large prediction jobs. |

**How to tune:** use `GridSearchCV` (try every combination with cross-validation, keep the best). Always choose settings using the **training data + CV**, never the test set.

## 4. Weighted KNN

**Problem with plain KNN:** a neighbour 0.1 away and a neighbour 10 away get the *same* vote. That feels wrong.

**Fix:** give each neighbour a **weight** that grows as distance shrinks. The usual choice is

```
weight = 1 / distance
```

### Regression with weights (same example as §2)
Neighbours of x = 4.2:

| Neighbour | Distance | Target | Weight (1/d) |
|---|---|---|---|
| x = 3 | 1.2 | 15 | 0.833 |
| x = 6 | 1.8 | 30 | 0.556 |
| x = 2 | 2.2 | 12 | 0.455 |

```
weighted prediction = Σ(weight × target) / Σ(weights)
                    = (0.833·15 + 0.556·30 + 0.455·12) / (0.833 + 0.556 + 0.455)
                    = 34.62 / 1.843
                    ≈ 18.78
```

Compared with the plain mean of **19.0**, the answer shifts toward the *closest* neighbour (target 15).

### Classification with weights
Add up the weights of each class instead of counting heads. The class with the largest total weight wins. This helps when a few very close points disagree with several far-away ones.

### Good to know
- If a neighbour has distance **0** (exact match), `1/0` blows up. Libraries handle this by returning that neighbour's value directly.
- Weighted KNN is **less sensitive to the choice of K**, because far neighbours barely count anyway.

## 5. Types of distances

"Nearest" only makes sense once you decide how to **measure distance**. Here we compare two points:

```
A = (1, 2, 3)      B = (4, 6, 3)      differences = (3, 4, 0)
```

| Distance | Formula | A↔B result | Intuition | Best for |
|---|---|---|---|---|
| **Euclidean** (L2) | `√Σ(aᵢ−bᵢ)²` | `√(9+16+0) =` **5** | Straight line ("as the crow flies") | Default; continuous, scaled features |
| **Manhattan** (L1) | `Σ|aᵢ−bᵢ|` | `3+4+0 =` **7** | Walking along city blocks | High dimensions, outliers, grid-like data |
| **Minkowski** (Lp) | `(Σ|aᵢ−bᵢ|ᵖ)^(1/p)` | p=3: **4.50** | General family; p=1 → Manhattan, p=2 → Euclidean | Tuning `p` as a hyperparameter |
| **Chebyshev** (L∞) | `max|aᵢ−bᵢ|` | **4** | Only the biggest single difference counts | When any one large gap matters (e.g. king moves in chess) |
| **Hamming** | number of positions that differ | `"karolin"` vs `"kathrin"` = **3** | Count of mismatches | Categorical / binary / text strings |
| **Cosine** (distance) | `1 − (a·b)/(‖a‖‖b‖)` | `1 − 0.855 =` **0.145** | Compares **direction**, ignores length | Text, embeddings, sparse data |

### Picture
```
Euclidean:  A ●
              \  5
               \
                ● B

Manhattan:  A ●────┐
                   │  3 + 4 = 7
                   └── ● B
```

### Choosing a distance — quick guide
- Numeric features, all scaled → **Euclidean** (start here).
- Many features, or outliers → try **Manhattan**.
- Categorical or yes/no features → **Hamming**.
- Text / document / embedding vectors → **Cosine**.
- Features that are strongly correlated → consider **Mahalanobis** (accounts for correlation; not covered in depth here).

> ⚠️ Whatever you pick, **scale the features first**. Otherwise the feature with the largest numbers decides everything.
> ⚠️ In scikit-learn, tree algorithms (`kd_tree`, `ball_tree`) support only some metrics; **cosine needs `algorithm="brute"`**.

## 6. Space and time complexity

**Notation:** `n` = training points · `d` = number of features · `K` = neighbours · `m` = number of queries.

### Brute-force KNN (compare against everything)

| Stage | Time | Space | Why |
|---|---|---|---|
| **Training** | **O(1)** | **O(n·d)** | Nothing to learn, just store the data. |
| **Predict 1 point** | **O(n·d + n log K)** | , | Compute `n` distances (each costs `d`), then pick the K smallest. |
| **Predict m points** | **O(m·n·d)** (roughly) | , | Repeat for each query. |

**The catch:** cheap to train, **expensive to use**. This is the opposite of most models (e.g. linear regression is slow-ish to train and instant to predict). With 1 million training rows, *every* prediction scans 1 million rows.

### With a KD-Tree

| Stage | Time | Space |
|---|---|---|
| **Build the tree** | **O(n log n)** (one-off, with median-finding) | O(n·d) |
| **Predict 1 point** | **O(log n)** on average in *low* dimensions; **O(n)** worst case | |

### Which algorithm wins? (rule of thumb)
- **Low `d`** (say d ≲ 20) and **large `n`** → **KD-tree / ball tree**, often massively faster.
- **High `d`** or small `n` → **brute force**. Trees stop pruning effectively (see "curse of dimensionality" in §7).

## 7. KD-Tree

**KD-Tree = "K-Dimensional tree".** (This `k` is the number of *dimensions*, unrelated to the K in KNN.)

### The idea
Brute force checks all `n` points. A KD-tree **organises the points once** so that, at prediction time, whole regions can be **skipped**. It is like looking up a word in a dictionary instead of reading every page.

### Building the tree
1. Pick an axis (cycle through the features: x, then y, then x, …).
2. Sort the points on that axis and take the **median** point as the node.
3. Points **smaller** go to the **left** subtree, **larger** go to the **right** subtree.
4. Repeat on each side with the next axis until no points remain.

**Example** points: `(7,2) (5,4) (9,6) (2,3) (4,7) (8,1)`

- Split on **x**: median = **(7,2)** → left `{(2,3),(4,7),(5,4)}`, right `{(8,1),(9,6)}`
- Left, split on **y**: median = **(5,4)** → (2,3) goes left, (4,7) goes right
- Right, split on **y**: median = **(9,6)** → (8,1) goes left

```
                 (7,2)            ← splits on x
               /       \
          (5,4)         (9,6)     ← split on y
          /   \         /
     (2,3)   (4,7)   (8,1)        ← split on x
```

Each node is also a **dividing line** in the plane, so the tree carves space into rectangles:

```
y
7|       (4,7)
6|                       (9,6)
4|     (5,4)
3|(2,3)
2|                 (7,2)
1|                           (8,1)
  +---------------------------------- x
              line x = 7 splits the plane first
```

### Searching for the nearest neighbour
**Query: (9, 2).** Follow these steps:

| Step | Action |
|---|---|
| 1 | At **(7,2)** (split x): 9 ≥ 7 → go **right**. |
| 2 | At **(9,6)** (split y): 2 < 6 → go **left**. |
| 3 | At **(8,1)**: distance = **1.41**. Best so far. |
| 4 | **Backtrack.** Is the splitting line of (9,6) closer than 1.41? Its gap is 4 → **no, prune** the other side. |
| 5 | Back at (7,2): gap to line x=7 is 2 → **no, prune** the left subtree. |

**Result:** nearest neighbour is **(8, 1)** at distance √2 ≈ 1.41, found after visiting **3 of 6 points**. With millions of points, the skipped fraction is huge.

### The pruning rule (the key trick)
> After finding a candidate at distance `r`, only look on the **other side** of a splitting line if that line is **closer than `r`**. Otherwise nothing over there can beat the candidate.

### Weaknesses
- **Curse of dimensionality:** as `d` grows, the query ball crosses almost every splitting line, so nothing gets pruned, and the tree degrades to roughly brute-force speed (or worse, because of the overhead).
- **Needs a rebuild** (or rebalancing) when data changes a lot.
- Works only with certain metrics (e.g. Euclidean, Manhattan, Chebyshev).

### Alternatives
- **Ball tree**: groups points into nested hyper-spheres; handles somewhat higher dimensions.
- **Approximate nearest neighbours** (FAISS, Annoy, HNSW): trade a tiny accuracy loss for huge speedups on very large or high-dimensional data.

## 8. Cheat sheet

```
KNN Regressor      → average (or weighted average) of K neighbours' targets
Weighted KNN       → weight = 1/distance; closer = louder voice
Distances          → Euclidean (default) · Manhattan · Minkowski · Chebyshev · Hamming · Cosine
Train cost         → O(1)             Predict cost → O(n·d) per query (brute force)
KD-Tree            → build O(n log n); query ~O(log n) if d is small, ~O(n) if d is large
Always             → scale features · tune K with cross-validation · don't tune on the test set
```

## 9. Self-check questions
1. A KNN regressor with K = 3 finds neighbours with targets 10, 20 and 60. What does it predict? *(Answer: 30)*
2. Why does weighted KNN usually need less careful tuning of K? *(Far neighbours barely count.)*
3. Which distance would you try for a binary yes/no feature vector? *(Hamming.)*
4. Why is KNN "fast to train but slow to predict"? *(No learning step, but each prediction scans all `n` points.)*
5. Why does a KD-tree struggle with 100 features? *(Pruning stops working in high dimensions.)*
6. Does changing `algorithm` from `brute` to `kd_tree` change the predictions? *(No, only the speed.)*

## 10. Glossary

| Term | Meaning |
|---|---|
| **Hyperparameter** | A setting chosen by you, not learned from data. |
| **Lazy learner** | A model that postpones all work until prediction time. |
| **Cross-validation** | Splitting training data into folds to estimate how well settings generalise. |
| **Median** | The middle value when sorted; keeps a KD-tree balanced. |
| **Pruning** | Skipping a branch because it provably cannot contain a closer point. |
| **Curse of dimensionality** | In high dimensions, points become nearly equidistant and spatial tricks stop working. |
| **RMSE / R²** | Regression error measures (lower RMSE, higher R² is better). |
