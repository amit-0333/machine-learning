## Part A: KNN regressor, weights, tuning, distances, speed

```python
import time
import numpy as np
import matplotlib.pyplot as plt
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split, GridSearchCV, cross_val_score
from sklearn.neighbors import KNeighborsRegressor
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import r2_score, mean_squared_error

# ---- 1. KNN regressor on noisy sine ----
rng = np.random.default_rng(0)
X = np.sort(rng.uniform(0, 10, 80)).reshape(-1, 1)
y = np.sin(X).ravel() + rng.normal(0, 0.25, 80)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0)
grid = np.linspace(0, 10, 300).reshape(-1, 1)
fig, axes = plt.subplots(1, 3, figsize=(15, 4), sharey=True)
for ax, k in zip(axes, [1, 7, 40]):
    m = KNeighborsRegressor(n_neighbors=k).fit(X_tr, y_tr)
    ax.scatter(X_tr, y_tr, s=15); ax.plot(grid, m.predict(grid), color="red")
    ax.set_title(f"K={k}  train R2={m.score(X_tr, y_tr):.2f}  test R2={m.score(X_te, y_te):.2f}")
plt.show()

# ---- 2. Uniform vs distance weights ----
for w in ["uniform", "distance"]:
    m = KNeighborsRegressor(n_neighbors=7, weights=w).fit(X_tr, y_tr)
    print(f"{w:9s} test R2 = {r2_score(y_te, m.predict(X_te)):.3f}")

# ---- 3. Tune hyperparameters on a real dataset ----
Xd, yd = load_diabetes(return_X_y=True)
Xd_tr, Xd_te, yd_tr, yd_te = train_test_split(Xd, yd, test_size=0.2, random_state=42)
pipe = Pipeline([("scale", StandardScaler()), ("knn", KNeighborsRegressor())])
params = {"knn__n_neighbors": range(1, 31), "knn__weights": ["uniform", "distance"], "knn__p": [1, 2]}
search = GridSearchCV(pipe, params, cv=5, scoring="neg_root_mean_squared_error").fit(Xd_tr, yd_tr)
print("Best params:", search.best_params_)
print("CV RMSE:", round(-search.best_score_, 2))
pred = search.predict(Xd_te)
print("Test RMSE:", round(mean_squared_error(yd_te, pred) ** 0.5, 2), "| Test R2:", round(r2_score(yd_te, pred), 3))

# ---- 4. Compare distance metrics ----
for metric in ["euclidean", "manhattan", "chebyshev", "cosine"]:
    p = Pipeline([("scale", StandardScaler()),
                  ("knn", KNeighborsRegressor(n_neighbors=15, metric=metric, algorithm="brute"))])
    print(f"{metric:10s} CV R2 = {cross_val_score(p, Xd_tr, yd_tr, cv=5, scoring='r2').mean():.3f}")

# ---- 5. Speed: brute vs kd_tree vs ball_tree ----
def bench(d, n=20000, nq=2000):
    r = np.random.default_rng(1)
    A, Q = r.normal(size=(n, d)), r.normal(size=(nq, d))
    out = {}
    for algo in ["brute", "kd_tree", "ball_tree"]:
        m = KNeighborsRegressor(n_neighbors=5, algorithm=algo).fit(A, r.normal(size=n))
        t = time.perf_counter(); m.predict(Q); out[algo] = time.perf_counter() - t
    return out
for d in [3, 50]:
    print(f"d={d}:", {k: f"{v:.3f}s" for k, v in bench(d).items()})
```

### What the output means

**1) K and the regression curve** (noisy sine wave, 24 test points)

| K | Train R² | Test R² | Reading |
|---|---|---|---|
| 1 | 1.00 | 0.76 | Memorises every point: wiggly curve (overfit) |
| 7 | 0.89 | 0.72 | Smooth curve following the sine |
| 40 | −0.13 | −0.26 | Almost flat: **underfit** (worse than predicting the mean) |

K = 1 and K = 7 score similarly on test because the test set is tiny (24 points), so small gaps are noise. This is exactly why we pick K with **cross-validation** (step 3) rather than one lucky split.

**2) Uniform vs distance weights**
```
uniform   test R2 = 0.722
distance  test R2 = 0.795
```
Giving closer neighbours more say improved test R² here.

**3) Tuning on the diabetes dataset**
```
Best params: {'knn__n_neighbors': 19, 'knn__p': 2, 'knn__weights': 'distance'}
CV RMSE: 58.63
Test RMSE: 54.41 | Test R2: 0.441
```
`GridSearchCV` tried 30 × 2 × 2 = 120 combinations with 5-fold CV. The test score is computed **once**, at the end. An R² of ~0.44 is typical for this dataset, which is noisy, so don't expect miracles from KNN here.

**4) Distance metrics** (K = 15, 5-fold CV R²)
```
euclidean  0.398    manhattan  0.370    chebyshev  0.391    cosine  0.398
```
Differences are small on this dataset. The metric matters most when features are binary, sparse or very high-dimensional.

**5) Speed test** (20,000 points, 2,000 queries)
```
d=3 : brute 0.125s | kd_tree 0.006s | ball_tree 0.047s
d=50: brute 0.187s | kd_tree 3.398s | ball_tree 2.304s
```
Timings vary by machine, but the pattern is stable:
- **Low dimension (d=3):** KD-tree is about **20× faster** than brute force.
- **High dimension (d=50):** the KD-tree becomes about **18× slower** than brute force. This is the curse of dimensionality in action.

> `algorithm="auto"` (the default) picks a sensible option for you, so you rarely need to set this by hand.

## Part B: KD-tree from scratch

This mirrors the walkthrough in the concepts README, using the same 6 points and the query `(9, 2)`.

```python
import numpy as np

class Node:
    def __init__(self, point, axis, left, right):
        self.point, self.axis, self.left, self.right = point, axis, left, right

def build(points, depth=0):
    """Split on x, then y, then x, ... at the median."""
    if not points:
        return None
    axis = depth % len(points[0])
    points = sorted(points, key=lambda p: p[axis])
    mid = len(points) // 2
    return Node(points[mid], axis,
                build(points[:mid], depth + 1),
                build(points[mid + 1:], depth + 1))

def nearest(node, q, best=None):
    """Return (distance, point) of the nearest neighbour of q."""
    if node is None:
        return best
    d = np.linalg.norm(np.array(node.point) - np.array(q))
    if best is None or d < best[0]:
        best = (d, node.point)
    diff = q[node.axis] - node.point[node.axis]
    near, far = (node.left, node.right) if diff < 0 else (node.right, node.left)
    best = nearest(near, q, best)          # 1) go down the likely side first
    if abs(diff) < best[0]:                # 2) could the other side hide something closer?
        best = nearest(far, q, best)       #    only then look there
    return best

points = [(7, 2), (5, 4), (9, 6), (2, 3), (4, 7), (8, 1)]
tree = build(points)
print(nearest(tree, (9, 2)))                # -> (1.414..., (8, 1))

# sanity check against brute force on random data
rng = np.random.default_rng(0)
pts = [tuple(p) for p in rng.uniform(0, 100, (500, 2))]
tree = build(pts)
for q in rng.uniform(0, 100, (50, 2)):
    brute = min(pts, key=lambda p: np.linalg.norm(np.array(p) - q))
    assert nearest(tree, tuple(q))[1] == brute
print("KD-tree matches brute force on 50 random queries")
```

Output:
```
(1.4142135623730951, (8, 1))
KD-tree matches brute force on 50 random queries
```

**How to read the code**
- `build` picks the **median** on the current axis and recurses, alternating x, y, x, …
- `nearest` first dives into the side of the splitting line the query is on.
- The line `if abs(diff) < best[0]` is the **pruning rule**: only search the far side if the splitting line is closer than the best distance found so far.
- The final loop proves the tree gives the **same answer as brute force**, just with fewer distance computations.

## Cheat sheet: scikit-learn parameters

```python
KNeighborsRegressor(
    n_neighbors=5,          # K
    weights="uniform",      # or "distance"
    algorithm="auto",       # "brute" | "kd_tree" | "ball_tree"
    leaf_size=30,           # tree speed/memory trade-off
    p=2,                    # 1 = Manhattan, 2 = Euclidean
    metric="minkowski",     # or "euclidean", "manhattan", "chebyshev", "cosine"
    n_jobs=None,            # -1 uses all CPU cores
)
```
Classifier version: `KNeighborsClassifier` takes the same parameters.

## Common mistakes
| Mistake | Fix |
|---|---|
| Forgetting to scale features | Put `StandardScaler` in a `Pipeline` before KNN |
| Choosing K by looking at test score | Use `GridSearchCV` / cross-validation on training data |
| Using `kd_tree` with 100+ features | Use `brute` (or approximate nearest neighbours) |
| Using `cosine` with `kd_tree` | Cosine requires `algorithm="brute"` |
| Expecting KNN to extrapolate | It can't; predictions stay inside the range of training targets |
