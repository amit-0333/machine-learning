## 1. Assumptions of Logistic Regression

Logistic regression, like other statistical methods, relies on certain assumptions.

### 1.1 The five assumptions

| # | Assumption | Meaning |
|---|---|---|
| 1 | **Binary dependent variable** | For *binary* logistic regression the outcome must have exactly two possible values: "yes" vs "no", "success" vs "failure", "spam" vs "not spam", etc. |
| 2 | **Independence of observations** | The observations should be independent of each other. The outcome of one instance should not affect the outcome of another. |
| 3 | **Linearity of independent variables and log odds** | LR does **not** require the dependent and independent variables to be related linearly, but it does require the independent variables to be **linearly related to the log odds**. |
| 4 | **Absence of multicollinearity** | Independent variables should not be too highly correlated with each other. Not a strict assumption, but multicollinearity makes the model unstable and difficult to interpret. |
| 5 | **Large sample size** | LR needs a reasonably large sample. A guideline: at least **10 cases of the least frequent outcome for each independent variable**. |

> Violating these assumptions doesn't mean you can't or shouldn't use logistic regression, but it may impact the validity of the results and you should **proceed with caution**.

### 1.2 Sample size rule worked out

```
minimum sample size = (10 × number of independent variables) / (probability of the least frequent outcome)
```

**Example:** 5 independent variables and the least frequent outcome has probability 0.10:

```
N = (10 × 5) / 0.10 = 500
```

(Intuition: you need 50 cases of the rare class; if it makes up only 10% of the data, you need 500 rows in total.)

### 1.3 How to check each assumption

| Assumption | Practical check | If violated |
|---|---|---|
| Binary target | Inspect `y.unique()` | Use multinomial/ordinal LR (Session 2 for multiclass) |
| Independence | Think about data collection (repeated measures? time series? clustered data?) | Use mixed-effects / GEE models, time-series methods |
| Linearity with log-odds | **Box-Tidwell test**, or bin a feature and plot the observed log-odds per bin | Transform the feature (log, sqrt), add **polynomial terms** (section 4), bin it |
| No multicollinearity | Correlation matrix, **VIF** (Variance Inflation Factor; VIF > 5 to 10 is a warning) | Drop/merge correlated features, PCA, or use **L2 regularization** |
| Sample size | Count events per variable (EPV) | Collect more data, reduce features, use regularization |

**Extra points worth knowing**

- LR does **not** assume normally distributed features, equal variances, or a linear relationship between features and the *probability*. (That's a common confusion with linear regression.)
- **Outliers / influential points** can distort coefficients, so check them even though it isn't listed as a formal assumption.
- **Perfect separation** (a feature perfectly predicts the class) makes coefficients blow up. Regularization fixes this.

## 2. Odds and Log(Odds)

### 2.1 Odds

> The **odds** of an event is the ratio of the probability of the event happening (P) to the probability of the event not happening (1 − P). It's a way of expressing the likelihood of an event.

```
odds = P / (1 − P)
```

- **odds > 1** → the event is more likely to happen than not.
- **odds = 1** → equally likely (P = 0.5).
- **odds < 1** → the event is less likely to happen than not.

**Probability vs odds:** probability is "favourable out of total"; odds is "favourable against unfavourable".

### 2.2 Conversion table

| Probability P | Odds = P/(1−P) | Read as | Log-odds = ln(odds) |
|---|---|---|---|
| 0.10 | 0.111 | 1 to 9 | −2.197 |
| 0.25 | 0.333 | 1 to 3 | −1.099 |
| 0.50 | 1 | 1 to 1 | **0** |
| 0.75 | 3 | 3 to 1 | 1.099 |
| 0.80 | 4 | 4 to 1 | 1.386 |
| 0.90 | 9 | 9 to 1 | 2.197 |

Going back from odds to probability: `P = odds / (1 + odds)`.

### 2.3 Why take the log of the odds?

| Quantity | Range | Problem |
|---|---|---|
| Probability P | 0 to 1 | Bounded, can't be modelled by a straight line |
| Odds | 0 to +∞ | Bounded below by 0, still asymmetric |
| **Log-odds (logit)** | **−∞ to +∞** | Unbounded and symmetric around 0, which matches the range of a linear expression `β0 + β1x1 + ...` |

```
logit(P) = ln( P / (1 − P) )
```

Log-odds are symmetric: `logit(0.8) = +1.386` and `logit(0.2) = −1.386`.

### 2.4 Odds ratio

If a coefficient is `β`, then increasing that feature by 1 unit multiplies the odds by `e^β`. This multiplier is the **odds ratio (OR)**.

| β | OR = e^β | Effect of +1 unit |
|---|---|---|
| 0 | 1 | no effect |
| 0.693 | 2 | odds double |
| 1.0 | 2.72 | odds × 2.72 |
| −0.693 | 0.5 | odds halve |

## 3. Another Interpretation of Logistic Regression

So far we saw LR as "a line + sigmoid, trained by maximum likelihood" (Session 1). Here's the other, more statistical way to see the same model.

### 3.1 The log-odds (logit) interpretation

> **Logistic regression is linear regression on the log-odds.**

```
ln( P / (1 − P) ) = β0 + β1·x1 + β2·x2 + ... + βd·xd
```

Solve for P to recover the sigmoid:

```
P / (1 − P) = e^z                      where z = β0 + β1·x1 + ...
P = e^z · (1 − P)
P · (1 + e^z) = e^z
P = e^z / (1 + e^z) = 1 / (1 + e^−z)   ← the sigmoid!
```

So **sigmoid is the inverse of the logit function**. Both views are the same model:

```
Features ──► linear combination z ──► (logit view)   z = ln(odds)
                                 └──► (sigmoid view) P = σ(z)
```

### 3.2 Consequences of this view

1. **Linear in log-odds, not in probability.** A one-unit increase in `xj` always adds `βj` to the log-odds, but the change in *probability* depends on where you start (large near P = 0.5, tiny near 0 or 1). This is the "S" shape.
2. **Multiplicative effects on odds.** Each feature multiplies the odds by `e^βj` (odds ratio).
3. **Assumption 3 explained.** The linearity assumption in Section 1 means exactly this: log-odds must be linear in the features.
4. **The decision boundary** (`P = 0.5` ⇔ odds = 1 ⇔ log-odds = 0 ⇔ `z = 0`) is a straight line/hyperplane.

### 3.3 Probabilistic (Generalized Linear Model) view

LR is a **Generalized Linear Model (GLM)**:

- **Random component:** `y ~ Bernoulli(P)`
- **Systematic component:** linear predictor `z = β0 + βᵀx`
- **Link function:** `logit(P) = z`

This is the setting where **maximum likelihood** gives the log-loss (see the MLE notes): the Bernoulli likelihood `P^y (1 − P)^(1−y)` leads to `L = −Σ[y ln P + (1−y) ln(1−P)]`.

### 3.4 Latent-variable view (optional)

Imagine an unobserved continuous score `y* = βᵀx + ε`, where the noise ε follows a **logistic distribution**. We observe only `y = 1` if `y* > 0`, else 0. Then `P(y = 1) = σ(βᵀx)`. (With normal noise you'd get *probit* regression instead.)

### 3.5 Worked example

Suppose a model for "placed" gives `z = −8 + 0.9·cgpa`.

- cgpa = 8: `z = −0.8` → `P = σ(−0.8) = 0.31`, odds = 0.45
- cgpa = 9: `z = 0.1` → `P = 0.52`, odds = 1.11
- Odds ratio per +1 cgpa = `e^0.9 = 2.46`. Check: 1.11 / 0.45 ≈ 2.46 ✓

## 4. Polynomial Features

### 4.1 The problem: a straight line is not enough

Logistic regression draws a **linear** decision boundary. For data like the "two interleaving half-moons" (red and cyan crescents), no straight line separates the classes: a line misclassifies many points.

### 4.2 The idea

Create **new features** that are powers (and products) of the originals, then fit an ordinary logistic regression on the expanded feature set.

**One feature, degree 2:**

```
x  ──►  [ x⁰, x¹, x² ]  = [1, x, x²]
z = β0 + β1·x + β2·x²
```

**Two features x1, x2, degree 2:**

```
[ 1, x1, x2, x1², x1·x2, x2² ]
z = β0 + β1·x1 + β2·x2 + β3·x1² + β4·x1·x2 + β5·x2²
```

(The handwritten notes list `x1⁰ x1¹ x1² x2⁰ x2¹ x2²`. scikit-learn additionally includes the interaction term `x1·x2`.)

### 4.3 Why this gives a non-linear boundary

The model is still **linear in the parameters β** (so everything we learned, like sigmoid, log loss and gradient descent, still applies). But the boundary `z = 0` is a **curve** in the original `(x1, x2)` space:

- degree 1 → straight line
- degree 2 → ellipse / parabola / hyperbola
- degree 3+ → increasingly wiggly curves

> *Linear in the expanded space ⇒ non-linear in the original space.*

### 4.4 Choosing the degree: the bias-variance trade-off

| Degree | Boundary | Result |
|---|---|---|
| Too **small** | Too simple (straight line) | **Underfitting**: high bias, misses the curve |
| Just right | Follows the true shape | Good generalization |
| Too **large** | Very wiggly, wraps around noise | **Overfitting**: high variance, great train score, poor test score |

**As the degree increases → the model's complexity increases → overfitting.** As the degree stays too small → underfitting.

**Number of features created** for `n` original features and degree `d` (including the bias column): `C(n + d, d)`.

| n | d = 2 | d = 3 | d = 5 | d = 10 |
|---|---|---|---|---|
| 2 | 6 | 10 | 21 | 66 |
| 10 | 66 | 286 | 3,003 | 184,756 |

The count explodes quickly, so large degrees are dangerous for high-dimensional data.

### 4.5 Code

```python
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import LogisticRegression

X, y = make_moons(n_samples=500, noise=0.25, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, stratify=y, random_state=42
)

for degree in [1, 2, 3, 5, 10, 15]:
    model = make_pipeline(
        PolynomialFeatures(degree, include_bias=False),   # LR adds its own intercept
        StandardScaler(),                                  # scale AFTER expanding
        LogisticRegression(C=1e4, max_iter=20000),         # large C = almost no regularization
    )
    model.fit(X_train, y_train)
    print(degree, round(model.score(X_train, y_train), 3), round(model.score(X_test, y_test), 3))
```

**Typical output** (train / test accuracy):

| Degree | Train | Test | Reading |
|---|---|---|---|
| 1 | 0.854 | 0.833 | underfit (straight line) |
| 2 | 0.851 | 0.847 | still too simple |
| **3** | 0.957 | **0.940** | big jump: the curve is captured |
| 5 | 0.960 | 0.940 | similar |
| 10 | 0.966 | 0.920 | train ↑, test ↓ → starting to overfit |
| 15 | 0.969 | 0.913 | overfitting: gap widens |

### 4.6 Tips

- Always **scale after** creating polynomial features (powers have very different magnitudes).
- Combine with **regularization** (section 5): use a somewhat high degree *and* let L2/L1 tame the coefficients.
- Choose `degree` via **cross-validation**, treating it as a hyperparameter.
- Alternatives for non-linear boundaries: kernel methods (SVM), decision trees / ensembles, neural networks.

## 5. Regularization in Logistic Regression

### 5.1 What and why

> **Regularization** is a technique used in machine learning models to prevent **overfitting**, which occurs when a model learns the noise along with the underlying pattern in the training data. Overfitting leads to poor generalization performance when the model is exposed to unseen data.

In linear models (linear and logistic regression), regularization works by **adding a penalty term to the loss function** that the model tries to minimize. The penalty **discourages the model from assigning too much importance to any single feature**, i.e. it keeps coefficients small.

```
Regularized loss  =  Data loss (log loss)  +  Penalty on the size of the weights
```

A sign of overfitting in logistic regression: very large coefficients (e.g., ±50), especially with polynomial features or perfectly separable data.

### 5.2 L1 Regularization (Lasso)

Adds a penalty equal to the **absolute value of the magnitude of the coefficients**: the sum of absolute values of the weights, `‖w‖₁`.

```
L_L1 = LogLoss + λ · Σⱼ |wⱼ|
```

- Can produce **sparse models**: some feature weights become **exactly zero**.
- Therefore useful for **feature selection**.

### 5.3 L2 Regularization (Ridge)

Adds a penalty equal to the **square of the magnitude of the coefficients**: the sum of squared weights, `‖w‖₂²`.

```
L_L2 = LogLoss + λ · Σⱼ wⱼ²
```

- Tends to **spread weight values more evenly across features**, giving smaller but **non-zero** weights.
- Handles correlated features gracefully (shares weight among them).

### 5.4 Elastic Net

A **combination of L1 and L2**. The contribution of each can be controlled with a separate hyperparameter (`l1_ratio`).

```
L_EN = LogLoss + λ · [ α·Σ|wⱼ| + (1 − α)·Σwⱼ² ]
```

`α = 1` → pure L1, `α = 0` → pure L2.

### 5.5 Comparison

| | L1 (Lasso) | L2 (Ridge) | Elastic Net |
|---|---|---|---|
| Penalty | Σ\|w\| | Σw² | mix of both |
| Weights | Many exactly **0** (sparse) | Small, rarely exactly 0 | Some zero, groups of correlated features kept together |
| Feature selection | **Yes** | No | Yes |
| Correlated features | Picks one arbitrarily | Shares weight | Shares weight + selects |
| Solution | Not smooth at 0 (needs special solvers) | Smooth, closed-form-friendly | Not smooth at 0 |
| Good default when... | Many irrelevant features | Most features matter a bit | Many correlated features |

**Geometric intuition:** minimizing the loss subject to a budget on the weights. The L1 budget region is a diamond with *corners on the axes*, so the optimum often lands on a corner where some weights are 0. The L2 region is a circle (no corners), so weights shrink but don't hit 0.

### 5.6 The hyperparameter λ (lambda)

The amount of regularization is controlled by **λ**.

| λ | Regularization | Model | Risk |
|---|---|---|---|
| **High** | Strong | Simpler | **Underfitting** |
| **Low** | Weak | More complex | **Overfitting** |
| 0 | None | Plain logistic regression | Overfit possible |

The optimal value of λ is typically found through **cross-validation**.

> **scikit-learn uses `C = 1/λ`** (inverse of regularization strength). **Small C → strong regularization. Large C → weak regularization.** Default `C = 1.0`.

### 5.7 Practical rules

- **Standardize features first.** The penalty treats all weights equally, so unscaled features are penalized unfairly.
- **Do not penalize the intercept** `β0` (scikit-learn doesn't).
- Regularization is on by default in scikit-learn (L2, `C=1`), so set `C` very large if you really want an unregularized fit.
- Regularization biases the coefficients toward zero. Interpret odds ratios with care.

### 5.8 Probabilistic view (links to MLE)

| Regularizer | Equivalent Bayesian prior on weights | Estimation |
|---|---|---|
| L2 | Gaussian prior `w ~ N(0, σ²)` | **MAP** estimate |
| L1 | Laplace prior | **MAP** estimate |

Plain LR = **MLE**. Regularized LR = **MAP (Maximum A Posteriori)**: maximum likelihood + prior belief that weights are small.

### 5.9 Code

```python
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

# L2 (default)
l2 = make_pipeline(StandardScaler(), LogisticRegression(C=1.0)).fit(X_train, y_train)

# L1: sparse weights
l1 = make_pipeline(
    StandardScaler(),
    LogisticRegression(l1_ratio=1.0, solver="saga", C=0.1, max_iter=10000),
).fit(X_train, y_train)

print("Zero weights with L1:", (l1[-1].coef_ == 0).sum(), "of", X.shape[1])
```

**Effect of C on L1 sparsity** (breast-cancer data, 30 features): `C = 0.01` → 27 weights are exactly 0; `C = 0.1` → 22; `C = 1` → 12. Smaller `C` means stronger regularization and sparser models.

> **Version note (scikit-learn).** Up to v1.7 you choose the regularizer with `penalty="l1" | "l2" | "elasticnet" | None` (plus `l1_ratio` for elastic net). In **v1.8** `penalty` is deprecated: use **`l1_ratio`** (0 = L2, 1 = L1, in between = elastic net) and `C=np.inf` for no regularization. The old syntax still works with a warning.

## 6. Hyperparameters

Hyperparameters are settings chosen **before** training (not learned from data). For logistic regression the important ones are:

| Hyperparameter | What it controls | Typical values |
|---|---|---|
| **`C`** (= 1/λ) | Regularization strength | `np.logspace(-4, 4, 9)`. Search on a **log scale** |
| **Penalty type** (`penalty` / `l1_ratio`) | L1, L2, elastic net or none | l2 (default), l1, elasticnet |
| **`solver`** | Optimization algorithm | `lbfgs` (default), `liblinear`, `newton-cg`, `newton-cholesky`, `sag`, `saga` |
| **`max_iter`** | Max iterations to converge | 100 (default); raise to 1000 to 10000 if you get a convergence warning |
| **`tol`** | Stopping tolerance | 1e-4 (default) |
| **`class_weight`** | Weights for classes (imbalanced data) | `None`, `"balanced"`, or a dict |
| **`fit_intercept`** | Whether to learn β0 | `True` |
| **Decision threshold** | Probability cut-off for class 1 | 0.5 default; tune for precision/recall trade-off |
| **Polynomial `degree`** | Complexity of the boundary (pipeline step) | 1 to 5 |

### 6.1 Which solver supports which penalty (classic `penalty` naming)

| Solver | L2 | L1 | Elastic net | None | Notes |
|---|---|---|---|---|---|
| `lbfgs` (default) | ✓ | ✗ | ✗ | ✓ | Good general default, small to medium data |
| `liblinear` | ✓ | ✓ | ✗ | ✗ | Good for small datasets; one-vs-rest only |
| `newton-cg` | ✓ | ✗ | ✗ | ✓ | |
| `newton-cholesky` | ✓ | ✗ | ✗ | ✓ | Many samples, few features; binary |
| `sag` | ✓ | ✗ | ✗ | ✓ | Fast on large data (scale features!) |
| `saga` | ✓ | ✓ | ✓ | ✓ | Only one supporting everything; large data |

### 6.2 Tuning tips

- Tune `C` on a **log scale** with `GridSearchCV` / `RandomizedSearchCV` (see the Hyperparameter Tuning notes).
- Put scaling and polynomial features in a **`Pipeline`** so they're fit inside each CV fold (no leakage).
- Pick the `scoring` metric that matches your goal (`roc_auc`, `f1`, `recall`, ...), not just accuracy.
- Always keep a final **test set** untouched.

## 7. Tasks (with Solutions)

### Task 1: Find the solution for the regularized loss function

**Setup.** For `n` samples, `ŷᵢ = σ(wᵀxᵢ + b)`.

**L2-regularized (Ridge) loss**

```
J(w, b) = −(1/n) Σᵢ [ yᵢ log ŷᵢ + (1 − yᵢ) log(1 − ŷᵢ) ]  +  (λ / 2n) · ‖w‖₂²
```

(The `1/2` is just to make the derivative neat. The bias `b` is not penalized.)

**Gradients**

```
∂J/∂w = (1/n) Xᵀ(ŷ − y) + (λ/n) · w
∂J/∂b = (1/n) Σᵢ (ŷᵢ − yᵢ)
```

The only change from un-regularized LR is the extra term `(λ/n)·w`.

**Is there a closed-form solution?** No. Setting `∂J/∂w = 0` involves the non-linear sigmoid, so we solve it **iteratively**. (Linear/ridge *regression* does have a closed form, `w = (XᵀX + λI)⁻¹Xᵀy`; logistic regression does not.)

**Gradient descent update (L2)**

```
w ← w − η · [ (1/n) Xᵀ(ŷ − y) + (λ/n) w ]
  = (1 − ηλ/n) · w  −  η · (1/n) Xᵀ(ŷ − y)
       └─ "weight decay": shrinks w a bit every step
b ← b − η · (1/n) Σ(ŷ − y)
```

The loss is **convex** (log loss is convex and the L2 term is strictly convex), so gradient descent reaches the **unique global minimum**.

**L1-regularized (Lasso) loss**

```
J(w, b) = LogLoss + (λ / n) · Σⱼ |wⱼ|
```

`|w|` isn't differentiable at 0. Use the **sub-gradient** `sign(wⱼ)` or, better, the **proximal (soft-thresholding)** update:

```
w ← w − η · (1/n) Xᵀ(ŷ − y)                         (usual gradient step)
w ← sign(w) · max( |w| − η·λ/n , 0 )                 (soft-threshold: pulls to exactly 0)
```

This is how sparse (zero) weights appear.

**Elastic net** adds both terms: gradient `+ (λ/n)(α·sign(w) + (1−α)·2w)` (or the proximal version).

**Relation to scikit-learn:** sklearn minimizes `C · Σ log-loss + ½‖w‖²`. Dividing by `C·n` shows it equals the form above with **λ = 1/C**.

**From-scratch implementation**

```python
import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def fit_regularized_lr(X, y, lam=1.0, lr=0.1, epochs=3000, penalty="l2"):
    n, d = X.shape
    w, b = np.zeros(d), 0.0
    for _ in range(epochs):
        p = sigmoid(X @ w + b)
        grad_w = X.T @ (p - y) / n
        grad_b = np.mean(p - y)

        if penalty == "l2":
            grad_w += (lam / n) * w                     # weight decay term
            w -= lr * grad_w
        else:                                           # "l1": proximal / soft-threshold
            w -= lr * grad_w
            w = np.sign(w) * np.maximum(np.abs(w) - lr * lam / n, 0)

        b -= lr * grad_b                                # intercept is not penalized
    return w, b
```

**What to observe** (breast-cancer data, standardized features):

| λ | ‖w‖ (size of weights) | Test accuracy |
|---|---|---|
| 0 | 4.22 | 0.974 |
| 1 | 3.37 | 0.982 |
| 10 | 1.83 | 0.974 |
| 100 | 0.83 | 0.947 |

Larger λ shrinks the weights; too much λ starts underfitting. The L2 solution with `lam=1` matches scikit-learn's `LogisticRegression(C=1.0)` closely, and the L1 version drives many weights to exactly 0.

### Task 2: Apply hyperparameter tuning to a real-world dataset

**Dataset:** Breast Cancer Wisconsin (569 samples, 30 features, binary: malignant / benign). Replace it with your own CSV if you like.

**Plan**

1. Split into train/test (stratified).
2. Build a `Pipeline`: `StandardScaler` → (optional `PolynomialFeatures`) → `LogisticRegression`.
3. Define a search space over `C`, regularization type and `class_weight`.
4. Run `GridSearchCV` with 5-fold CV and a sensible metric (ROC-AUC).
5. Inspect `cv_results_`, then evaluate **once** on the test set.

```python
import numpy as np
import pandas as pd
from scipy.stats import loguniform
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, GridSearchCV, RandomizedSearchCV
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report, roc_auc_score

# 1. Data
X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)

# 2. Pipeline  (saga supports L1, L2 and elastic net)
pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("clf", LogisticRegression(solver="saga", max_iter=10000)),
])

# 3. Search space  (l1_ratio: 0 = L2, 0.5 = elastic net, 1 = L1; needs scikit-learn >= 1.8.
#    On older versions use penalty=["l1","l2"] / "elasticnet" with l1_ratio instead)
param_grid = {
    "clf__C": np.logspace(-3, 3, 7),            # 0.001 ... 1000 on a log scale
    "clf__l1_ratio": [0, 0.5, 1],
    "clf__class_weight": [None, "balanced"],
}

# 4. Grid search
grid = GridSearchCV(pipe, param_grid, scoring="roc_auc", cv=5, n_jobs=-1, verbose=1)
grid.fit(X_train, y_train)

print("Best params :", grid.best_params_)
print("Best CV AUC :", round(grid.best_score_, 4))

# 5. Final evaluation
best = grid.best_estimator_
print("Test AUC    :", round(roc_auc_score(y_test, best.predict_proba(X_test)[:, 1]), 4))
print(classification_report(y_test, best.predict(X_test), digits=3))

# Inspect all runs
results = pd.DataFrame(grid.cv_results_)
print(results[["params", "mean_test_score", "std_test_score", "rank_test_score"]]
      .sort_values("rank_test_score").head(10))

# Optional: faster random search over a continuous C
rand = RandomizedSearchCV(
    pipe,
    {"clf__C": loguniform(1e-3, 1e3), "clf__l1_ratio": [0, 0.5, 1]},
    n_iter=20, scoring="roc_auc", cv=5, random_state=42, n_jobs=-1,
).fit(X_train, y_train)
print(rand.best_params_, rand.best_score_)
```

**Typical result** (will vary slightly with version/seed): best `C ≈ 0.1`, L2 penalty, `class_weight="balanced"`; CV AUC ≈ 0.994, test AUC ≈ 0.996, accuracy ≈ 96 to 97%. Moderate regularization wins because the data has many correlated features.

## 8. Summary & Cheat Sheet

1. **Assumptions:** binary target, independent observations, **log-odds linear in features**, no severe multicollinearity, enough data (≈ 10 events per variable).
2. **Odds** = P/(1−P); **log-odds (logit)** = ln(odds) ∈ (−∞, ∞). `e^β` is the **odds ratio**.
3. **Interpretation:** LR is linear regression on log-odds; **sigmoid is the inverse of logit**.
4. **Polynomial features** (`x, x², x³, …`) let a *linear* model draw a *non-linear* boundary. A low degree → underfit, a high degree → overfit.
5. **Regularization** adds a weight penalty to the loss to prevent overfitting:
   - **L1** → sparse weights (feature selection)
   - **L2** → small, spread-out weights
   - **Elastic net** → a mix
   - λ high → underfit, λ low → overfit; sklearn uses **C = 1/λ**; find it by cross-validation.
6. **Gradient of the regularized loss (L2):** `(1/n)Xᵀ(ŷ − y) + (λ/n)w`; there is no closed form, so use gradient descent.
7. **Tune** `C`, penalty, solver, class_weight (and polynomial degree) with a `Pipeline` + `GridSearchCV`/`RandomizedSearchCV`.

```
Raw features ─► [Scale] ─► [Polynomial features] ─► Logistic Regression (+ L1/L2 penalty, C)
                                                         │
                                  tune C, degree, penalty with cross-validation
```
