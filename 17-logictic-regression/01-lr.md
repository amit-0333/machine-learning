## 1. Introduction

**Logistic Regression** is a **supervised learning** algorithm used for **classification**, mostly binary classification (two classes, e.g. placed / not placed, spam / not spam, fraud / not fraud).

Despite the word "regression" in its name, it predicts a **class** (via a probability), not a continuous number. It is called regression because internally it fits a **linear equation** to the inputs; that value is then squashed into a probability.

**Running example used in the notes:** predict whether a student gets placed (`1`) or not (`0`) from two features, `cgpa` (x1) and `iq` (x2).

Key idea in one line:

> Find a line (a plane in higher dimensions) that separates the two classes, then turn the *distance from that line* into a *probability*.

---

## 2. Some Basic Geometry

Logistic regression is built on simple coordinate geometry, so we first need three facts.

### 2.1 Every line has a positive side and a negative side

A line in 2D is written as

```
A·x + B·y + C = 0
```

or, in the machine learning notation used in the course:

```
β0 + β1·x1 + β2·x2 = 0
```

This line cuts the plane into **two regions**:

- **Positive region**: where `β0 + β1·x1 + β2·x2 > 0`
- **Negative region**: where `β0 + β1·x1 + β2·x2 < 0`

Which side is "positive" is decided by the signs of the coefficients. The **normal vector** `(β1, β2)` points toward the positive side.

### 2.2 How to find whether a given point lies on a given line?

Substitute the point's coordinates into the line equation.

| Result of `β0 + β1·x1 + β2·x2` | Meaning |
|---|---|
| `= 0` | Point lies **on** the line |
| `> 0` | Point lies on the **positive** side |
| `< 0` | Point lies on the **negative** side |

**Example:** line `2x + 3y − 6 = 0`

| Point | Calculation | Result | Position |
|---|---|---|---|
| (3, 0) | 2(3) + 3(0) − 6 | 0 | on the line |
| (4, 2) | 2(4) + 3(2) − 6 | 8 | positive side |
| (0, 0) | 2(0) + 3(0) − 6 | −6 | negative side |

### 2.3 Generalizing to many features

With `d` features, the "line" becomes a **hyperplane**, and the formula in vector form is

```
z = β0 + β1·x1 + β2·x2 + ... + βd·xd = β0 + βᵀx
```

- `β0` is the **intercept (bias)**.
- `β1 ... βd` are the **coefficients (weights)**, one per feature.
- The value `z` is proportional to the **signed distance** of the point from the hyperplane: the further from the line, the larger `|z|`; the sign tells the side.

---

## 3. The Problem

### 3.1 What are we trying to do?

In a classification problem we want to make sure that

> **positive (+ve) points land in the +ve region and negative (−ve) points land in the −ve region.**

So the task is to find the coefficients `β0, β1, β2` of a line that separates the two classes.

### 3.2 The simple algorithm (hard / "step" classification)

1. Start with some random line.
2. For every point, compute `z = β0 + β1·x1 + β2·x2`.
3. If `z > 0`, predict class 1; otherwise predict class 0. This is a **step function**.
4. If a point is on the wrong side, **move the line** to correct it. Repeat. (This is the idea behind the *perceptron trick*.)

### 3.3 What is wrong with this?

| Problem | Explanation |
|---|---|
| **Black and white output** | A point just 0.001 units across the line and a point very far away both get exactly the same label, "1". No sense of confidence. |
| **No notion of "best" line** | If the data is separable, infinitely many lines work equally well. The step approach stops at the first line that classifies everything correctly, which may be a poor one. |
| **Not differentiable** | The step function has no useful slope, so we can't use gradient-based optimization to improve the line. |
| **Fails on non-separable data** | If classes overlap (the real-world case), no line gets every point right, and the algorithm keeps flipping without converging. |

This leads to the improvement below.

---

## 4. New Problem Formulation

> **Classification should not be so black and white.**

Instead of a hard yes/no, let the model output a **probability**:

> "This student is placed with probability 0.7."

The intuition (as drawn in the notes):

| Where the point lies | Desired output (probability of class 1) |
|---|---|
| Exactly on the line | **0.5** (completely unsure) |
| A little on the positive side | 0.6 |
| Further into the positive side | 0.7, 0.9, ... → approaches **1** |
| A little on the negative side | 0.4 |
| Further into the negative side | 0.3, 0.1, ... → approaches **0** |

So we need a smooth function that maps the signed distance `z ∈ (−∞, +∞)` to a probability in `(0, 1)`. That function is the **sigmoid**.

```
z = β0 + β1·x1 + β2·x2        →        ŷ = σ(z)  ∈ (0, 1)
```

---

## 5. Sigmoid Function

### 5.1 Definition

```
σ(z) = 1 / (1 + e^(−z))
```

Also called the **logistic function** (this is where the algorithm gets its name).

### 5.2 Behaviour

| z | σ(z) | Reading |
|---|---|---|
| z → −∞ | → 0 | very sure it's class 0 |
| z = −2 | ≈ 0.12 | |
| **z = 0** | **0.5** | on the decision boundary |
| z = 2 | ≈ 0.88 | |
| z → +∞ | → 1 | very sure it's class 1 |

(As the notes say: as `x → ∞`, `y → 1` (it "tries to touch 1" but never does); as `x → −∞`, `y → 0`; at `x = 0`, `y = 0.5`.)

### 5.3 Useful properties

- **Range:** strictly between 0 and 1, so it can be read as a probability.
- **Smooth and differentiable everywhere**, which makes gradient descent possible.
- **Symmetry:** `σ(−z) = 1 − σ(z)`.
- **Neat derivative:** `σ'(z) = σ(z) · (1 − σ(z))`.
- **Monotonic:** larger `z` always gives a larger probability.

### 5.4 The full model

Putting the line and the sigmoid together:

```
ŷ = P(y = 1 | x) = 1 / (1 + e^−(β0 + β1·x1 + β2·x2))
```

### 5.5 From probability to class: the decision threshold

```
predicted class = 1   if ŷ ≥ 0.5
                  0   otherwise
```

Because `σ(z) ≥ 0.5` exactly when `z ≥ 0`, the **decision boundary is still the straight line** `β0 + β1·x1 + β2·x2 = 0`. Logistic regression is therefore a **linear classifier**.

The threshold 0.5 can be changed. In cancer or fraud detection you may use 0.3 to catch more positives (higher recall).

### 5.6 Why "log-odds"?

If `p = σ(z)`, then

```
p / (1 − p) = e^z        (odds)
log( p / (1 − p) ) = z   (log-odds, or "logit")
```

So logistic regression assumes the **log-odds are a linear function of the features**. This is the key to interpreting coefficients (see section 10).

## 6. Maximum Likelihood

### 6.1 The question

The sigmoid gives us a probability for any line `(β0, β1, β2)`. But **which line is the best?** We need a score that measures how good a line is.

### 6.2 Likelihood

> **The likelihood function is the product of the predicted probabilities for the actual class of each observation.**

- If a point is truly class **1**, take the model's probability of 1: `ŷ`.
- If a point is truly class **0**, take the model's probability of 0: `1 − ŷ`.
- **Multiply** these together across all points.

For one point: `P(y | x) = ŷ^y · (1 − ŷ)^(1−y)`

For all points: `Likelihood = ∏ ŷᵢ^yᵢ · (1 − ŷᵢ)^(1−yᵢ)`

### 6.3 Worked example from the notes

Compare two candidate lines (Model 1 and Model 2) on the same 4 points. For each point we write the probability the model gave to the point's **true** class:

| | Point 1 | Point 2 | Point 3 | Point 4 | Likelihood (product) |
|---|---|---|---|---|---|
| **Model 1** | 0.8 | 0.6 | 0.7 | 0.6 | 0.8 × 0.6 × 0.7 × 0.6 = **0.2016 ≈ 0.20** |
| **Model 2** | 0.7 | 0.4 | 0.3 | 0.6 | 0.7 × 0.4 × 0.3 × 0.6 = **0.0504 ≈ 0.05** |

**Model 1 has the higher likelihood, so Model 1 is the better line.**

### 6.4 Maximum Likelihood Estimation (MLE)

> Choose the `β` values that **maximize** the likelihood. That gives the **best line**, the best logistic regression model.

Intuition: the best model is the one that makes the observed data *most probable*, assigning high probability to the correct class of every point.

### 6.5 The problem with a raw product

- Multiplying thousands of numbers below 1 gives a tiny number → **numerical underflow**.
- Products are awkward to differentiate.

The fix is to take the **logarithm**.

## 7. Log Loss

### 7.1 From likelihood to log-likelihood

Since `log` is an increasing function, maximizing the likelihood is the same as maximizing its log, and the log turns the **product into a sum**:

```
log-likelihood = Σ [ yᵢ·log(ŷᵢ) + (1 − yᵢ)·log(1 − ŷᵢ) ]
```

### 7.2 From maximizing to minimizing

Optimizers are conventionally written as **minimizers**, so we negate it and average over `n` points. This is the **Log Loss**, also called **Binary Cross-Entropy (BCE)**:

```
L(β) = −(1/n) · Σᵢ [ yᵢ·log(ŷᵢ) + (1 − yᵢ)·log(1 − ŷᵢ) ]
```

> **Maximize likelihood ⇔ Minimize log loss.**

### 7.3 How to read the formula

For each point only one of the two terms is active:

| True label | Loss for that point | Meaning |
|---|---|---|
| y = 1 | `−log(ŷ)` | small if ŷ is near 1, **huge** if ŷ is near 0 |
| y = 0 | `−log(1 − ŷ)` | small if ŷ is near 0, **huge** if ŷ is near 1 |

So **confident wrong predictions are punished very heavily**, while confident correct ones cost almost nothing.

### 7.4 Same worked example in log loss

| | −log of each probability | Sum | Mean (log loss) |
|---|---|---|---|
| Model 1 (0.8, 0.6, 0.7, 0.6) | 0.223, 0.511, 0.357, 0.511 | 1.601 | **0.400** |
| Model 2 (0.7, 0.4, 0.3, 0.6) | 0.357, 0.916, 1.204, 0.511 | 2.988 | **0.747** |

Model 1 has the **lower** loss, so it is better, matching the likelihood conclusion.

### 7.5 Why log loss is a good loss function

- **Convex** in `β` for logistic regression, so there is a **single global minimum** and no bad local minima.
- Smooth and differentiable.
- A proper probabilistic loss: it rewards well-calibrated probabilities, not only correct labels.
- Why not Mean Squared Error? With a sigmoid, MSE makes the loss non-convex and the gradients tiny when the model is confidently wrong. Log loss avoids both problems.

## 8. Gradient Descent

### 8.1 Why we need it

Setting the derivative of log loss to zero has **no closed-form solution** (unlike linear regression's normal equation). So we find the minimum **iteratively**.

### 8.2 The idea

Imagine standing on a hill (the loss surface) in fog. Feel the slope under your feet and take a small step **downhill**. Repeat until you reach the bottom.

### 8.3 The algorithm

```
1. Initialize β0, β1, ..., βd  (e.g., zeros or small random numbers)
2. Repeat until convergence:
     a. Compute predictions   ŷ = σ(β0 + β1·x1 + ...)
     b. Compute gradient of the loss with respect to every β
     c. Update:  β ← β − η · gradient
```

`η` (eta) is the **learning rate**, the step size.

### 8.4 The gradient

Using `σ'(z) = σ(z)(1 − σ(z))`, the derivative of log loss simplifies beautifully:

```
∂L/∂βj = (1/n) · Σᵢ (ŷᵢ − yᵢ) · xᵢⱼ          for j = 1..d
∂L/∂β0 = (1/n) · Σᵢ (ŷᵢ − yᵢ)                 (x for the intercept is 1)
```

**Vectorized** (X is the n × d feature matrix):

```
∇β L = (1/n) · Xᵀ (ŷ − y)
```

Notice it is **prediction − actual**, times the feature. The same form as in linear regression.

**Derivation sketch (for one sample):**

```
L  = −[ y·log(ŷ) + (1−y)·log(1−ŷ) ],   ŷ = σ(z),   z = βᵀx

∂L/∂ŷ = −y/ŷ + (1−y)/(1−ŷ) = (ŷ − y) / (ŷ(1 − ŷ))
∂ŷ/∂z = ŷ(1 − ŷ)
∂z/∂βj = xj

∂L/∂βj = (ŷ − y)/(ŷ(1−ŷ)) · ŷ(1−ŷ) · xj = (ŷ − y)·xj
```

### 8.5 Update rule

```
βj ← βj − η · (1/n) · Σᵢ (ŷᵢ − yᵢ) · xᵢⱼ
```

**Intuition:** if the model predicts too high for a point with positive feature value (`ŷ − y > 0`), the corresponding weight is pushed down, and vice versa.

### 8.6 Variants

| Variant | Uses per update | Notes |
|---|---|---|
| **Batch GD** | All n samples | Stable, slow on big data |
| **Stochastic GD (SGD)** | 1 sample | Fast and noisy |
| **Mini-batch GD** | A small batch (e.g., 32/64) | The common practical choice |

### 8.7 Practical tips

- **Scale your features** (e.g., `StandardScaler`). Otherwise the loss surface is elongated and convergence is slow.
- **Learning rate:** too large → loss oscillates or diverges; too small → very slow. Plot loss vs. iteration to check.
- **Regularization:** add an L2 (or L1) penalty to prevent overfitting. Scikit-learn does this by default (`C=1.0`, where `C = 1/λ`, so smaller `C` means stronger regularization).
- scikit-learn doesn't use plain gradient descent by default but solvers such as `lbfgs`, `liblinear`, `saga`; they optimize the same loss.

## 9. Full Code

### 9.1 From scratch (NumPy)

```python
import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

class MyLogisticRegression:
    def __init__(self, lr=0.1, epochs=1000):
        self.lr = lr
        self.epochs = epochs

    def fit(self, X, y):
        n, d = X.shape
        self.w = np.zeros(d)      # β1..βd
        self.b = 0.0              # β0
        self.losses = []

        for _ in range(self.epochs):
            p = sigmoid(X @ self.w + self.b)          # predictions ŷ
            grad_w = X.T @ (p - y) / n                # ∂L/∂w
            grad_b = np.mean(p - y)                   # ∂L/∂b
            self.w -= self.lr * grad_w
            self.b -= self.lr * grad_b

            eps = 1e-12                               # avoid log(0)
            loss = -np.mean(y * np.log(p + eps) + (1 - y) * np.log(1 - p + eps))
            self.losses.append(loss)
        return self

    def predict_proba(self, X):
        return sigmoid(X @ self.w + self.b)

    def predict(self, X, threshold=0.5):
        return (self.predict_proba(X) >= threshold).astype(int)
```

Usage:

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import accuracy_score

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)

scaler = StandardScaler().fit(X_train)          # fit on TRAIN only
X_train_s, X_test_s = scaler.transform(X_train), scaler.transform(X_test)

model = MyLogisticRegression(lr=0.1, epochs=1000).fit(X_train_s, y_train)
print("Test accuracy:", accuracy_score(y_test, model.predict(X_test_s)))
print("Loss: start", model.losses[0], "-> end", model.losses[-1])
```

The loss should fall steadily from about 0.69 (= ln 2, the loss of always guessing 0.5) to a small value, and test accuracy should be high (~97% on this dataset).

### 9.2 With scikit-learn

```python
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

clf = make_pipeline(StandardScaler(), LogisticRegression())
clf.fit(X_train, y_train)

print(clf.score(X_test, y_test))
print(clf.predict_proba(X_test[:3]))        # [P(class 0), P(class 1)] per row

lr = clf.named_steps["logisticregression"]
print(lr.intercept_)                         # β0
print(lr.coef_)                              # β1..βd
```

## 10. Interpreting the Model

Since `log(p / (1 − p)) = β0 + β1·x1 + ...`:

- **`βj` > 0** → increasing `xj` raises the probability of class 1; **`βj` < 0** lowers it.
- **`e^βj` = odds ratio:** for a one-unit increase in `xj` (others fixed), the **odds** of class 1 are multiplied by `e^βj`.
  - `βj = 0.7` → `e^0.7 ≈ 2.01`: the odds double.
  - `βj = −0.7` → `e^−0.7 ≈ 0.50`: the odds halve.
- Compare coefficient magnitudes **only when features are on the same scale**.

## 11. Assumptions, Pros & Cons

**Assumptions**

- Target is binary (for the basic version).
- Observations are independent.
- Log-odds are roughly **linear** in the features (otherwise add polynomial/interaction terms).
- Little **multicollinearity** between features (it makes coefficients unstable).
- Enough samples per class (common rule of thumb: at least ~10 events per feature).

**Pros**

- Simple, fast, and a strong baseline.
- Outputs **probabilities**, not only labels.
- **Interpretable** coefficients.
- Convex loss → reliable training; works well with regularization.

**Cons**

- Only a **linear** decision boundary (cannot solve XOR-like patterns without feature engineering).
- Sensitive to outliers and to correlated features.
- Needs feature scaling for gradient-based solvers.
- Perfectly separable data can make coefficients grow very large (regularization fixes this).

**Evaluation tip:** accuracy alone misleads on imbalanced data. Use the confusion matrix, precision, recall, F1, ROC-AUC and PR-AUC.

## 12. Summary

1. **Goal:** classify points using a line/hyperplane `z = β0 + β1·x1 + ... + βd·xd`; the sign of `z` tells the side of the line.
2. **Problem with hard (step) classification:** it is all-or-nothing, has no notion of confidence, and can't be optimized smoothly.
3. **Fix:** pass `z` through the **sigmoid** to get a probability, `ŷ = 1 / (1 + e^−z)`; the line itself (`z = 0`, `ŷ = 0.5`) is the decision boundary.
4. **Which line is best?** The one with **maximum likelihood**, i.e. the highest product of predicted probabilities of the true classes.
5. **Practical form:** take the log and negate → **Log Loss / Binary Cross-Entropy**; maximize likelihood ⇔ minimize log loss.
6. **How to minimize:** **gradient descent** with the neat gradient `(1/n) Xᵀ(ŷ − y)`.
7. **Output:** probability → apply a threshold (default 0.5) to get the class.

```
Features x ──► z = β0 + βᵀx ──► ŷ = σ(z) ──► threshold ──► class
                    ▲                │
                    └── gradient descent on log loss ◄──┘
```
